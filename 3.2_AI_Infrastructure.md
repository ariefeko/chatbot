## 3.2 AI Infrastructure

### Objective

AI Infrastructure provides the technical foundation for running the chatbot reliably, securely, and at enterprise scale.

The chatbot should be implemented as a separate AI service, not tightly coupled to the Domain website codebase. The website should only embed the chatbot widget and communicate with the AI backend through secure APIs.

---

### AI Infrastructure Architecture

```text
Domain Website
      │
      ▼
Chatbot Widget
      │
      ▼
AI Backend API
      │
      ▼
AI Orchestrator
      │
      ├── LLM Provider
      ├── Vector Database
      ├── Knowledge Indexer
      ├── Cache
      ├── Queue Worker
      ├── Business API Connector
      └── Logging & Monitoring
```

---

### Core Components

| Component | Purpose |
|---|---|
| Chatbot Widget | Website chat interface |
| AI Backend API | Entry point for chatbot requests |
| AI Orchestrator | Controls AI workflow and business logic |
| Vector Database | Stores searchable knowledge embeddings |
| Knowledge Indexer | Converts articles, FAQ, and product data into searchable knowledge |
| Cache | Reduces repeated AI/API calls |
| Queue Worker | Handles slow or background processes |
| LLM Provider | Generates AI responses |
| Monitoring | Tracks performance, errors, and usage |

---

### Infrastructure Principles

The infrastructure should be:

- Modular
- Scalable
- Secure
- Observable
- Vendor-neutral
- Easy to maintain
- Separated from the main website application

The AI service should be replaceable or upgradeable without requiring major changes to Domain.co.id.

---

### Knowledge Infrastructure

Official Domain content should be processed into a searchable knowledge base.

```text
CMS Articles / FAQ / Product Data
        ↓
Knowledge Indexer
        ↓
Embedding Model
        ↓
Vector Database
        ↓
RAG Retrieval
        ↓
AI Orchestrator
```

This allows the chatbot to answer using official website content instead of relying only on the model’s general knowledge.

---

### Performance Considerations

To reduce latency and cost, the infrastructure should support:

- Response caching
- Knowledge retrieval optimization
- API timeout handling
- Retry mechanism
- Queue for long-running tasks
- Fallback model/provider
- Rate limiting

---

### Observability

The platform should capture:

- Request logs
- AI response latency
- LLM token usage
- Retrieval results
- Error rate
- Escalation rate
- User feedback
- Cost per conversation

This helps the business measure chatbot quality, performance, and operational cost.
